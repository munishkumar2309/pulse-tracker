# Architecture

## Stack
| Layer | Choice | Why |
|---|---|---|
| UI | React 19 + TypeScript 7, Vite 8 | Fast to change, web code reused inside the Android app |
| Styling | Tailwind CSS 4, tokens in `src/index.css` | Theme via CSS variables (dark + light) |
| Routing | React Router 8, **HashRouter** | Works from `file://` in the Android WebView |
| Storage | Dexie 4 (IndexedDB), on device only | Same code in browser and WebView; no server |
| Charts | Recharts 3 | Trends screen |
| Icons / font | lucide-react, Archivo variable (bundled via @fontsource, offline) | |
| Tests | Vitest 5 (`npm test`) | Pure logic is tested; UI is checked in a browser |
| Android | Capacitor 8 + own SMS plugin + @capgo/capacitor-health | built by GitHub Actions (docs/ANDROID.md) |

## Data flow
- Screens read through `useLiveQuery` (Dexie). Any DB write re-renders the screens that depend on it, so there is no global state store.
- Writes: transactions only through `money/ingest.ts`. Health entries are written directly from `components/LogSheets.tsx` and `screens/ProfileForm.tsx`.
- Pure logic (`health/*`, `money/smsParser|categorize|insights`, `lib/format`) never touches the DB. Keep it that way so it stays testable.

## Database schema (`src/db/schema.ts`, version 1)
| Table | Key / indexes | Notes |
|---|---|---|
| profile | `id` ('me') | sex, dob, heightCm, activity, goalWeightKg, paceKgPerWeek, stepGoal, sleepGoalMin, bmiStandard, waterGoalMl? |
| weights | `++id`, date | kg, source |
| water | `++id`, date | ml, at |
| steps | `date` | one row per day, count, source |
| sleep | `++id`, date | date = day you woke; start/end ISO; minutes; stages? |
| transactions | `id`, date, category, merchantKey, type, [date+type] | amountPaise (integer), excluded = not counted as spend, userSet = category picked by hand (auto re-categorising skips it) |
| rules | `merchantKey` | user's "always use this category" choices |
| budgets | `category` | monthlyPaise |
| foods | `id`, name, barcode, source | (Phase 3) per100g nutrition, serving |
| foodLogs | `++id`, date, [date+meal] | kcal/protein/carbs/fat snapshot at log time |
| walks (v2) | `++id`, date, start | GPS walks: distanceM, movingS, points [lat,lng,ms][], kcal |
| meta | `key` | misc (last SMS sync etc.) |

**Changing the schema:** add `db.version(2).stores({...}).upgrade(...)`. Never edit version 1 once a build has been installed on the phone.

## Conventions
- Money is integer **paise**. Show it with `formatINR`.
- Day keys are local `YYYY-MM-DD` from `dayKey()`. Never use `toISOString().slice(0,10)`, which gives the UTC date and is off by one before 05:30 IST.
- Dev seeding: `window.db` is available in the browser console under `npm run dev`.
